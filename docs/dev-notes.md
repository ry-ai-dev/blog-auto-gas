## 段階2: Claude APIによる記事生成(実測値)

- 所要時間: 1記事あたり約30〜43秒(`UrlFetchApp.fetch` のタイムアウトは約60秒とされているため、余裕は約17秒程度)
- トークン数: 1記事あたり 入力約1,900トークン / 出力約5,900トークン程度
- コスト目安: 1記事あたり約10円(単価は入力$2 / 出力$10 per 100万トークンで概算。実際の料金は公式サイトで要確認)
- 落とし穴: キーワード「勤怠管理システム 比較 選び方」で max_tokens(当時6000)に達し出力が途中で切れJSON解析に失敗した事例があったため、MAX_TOKENSを8000に拡大し、プロンプト側の文字数目安も調整した

## 段階3: WordPress下書き保存(操作メモ)

- 何をしたか
  - `postDraftToWordPress()` を追加。メニュー「記事生成」→「WordPressに下書き保存(選択行)」から実行する(記事生成とは別操作)
  - 選択行のステータスが「生成済み」であること、タイトル・本文が入っていること、J列(投稿ID)が未設定であることを確認してから送信する
  - 送信前に `<script>` / `<iframe>` / `on○○=` 属性を除去するサニタイズを実施
  - `status` は常に `'draft'` 固定(コード上で変更できない)
- DRY_RUNの使い方
  - スクリプトプロパティ `DRY_RUN` が `'false'` と明示されている場合のみ本番投稿。未設定・それ以外の値はすべて試運転として扱う
  - 試運転では通信を行わず、送信先ホスト名・タイトル・本文の文字数・excerptの文字数・status(draft)をダイアログ表示するだけ。パスワードやヘッダーは表示しない
  - 試運転ではステータス・シート内容を変更しないため、何度でも再実行できる
- 本番切替の手順
  1. スクリプトプロパティに `WP_URL`(`https://` で始まるサイトURL)・`WP_USER`・`WP_APP_PASSWORD` を設定する
  2. 動作確認(試運転)でダイアログの内容(タイトル・文字数など)を確認する
  3. 問題なければスクリプトプロパティ `DRY_RUN` を `false` に変更し、再度メニューを実行する
  4. 成功するとJ列に投稿ID、E列に投稿URL(取得できた場合)が入り、ステータスが「下書き保存済み」になる
- WordPress側で必要な準備
  - 投稿者権限(Author以上)を持つ専用ユーザーを用意する(管理者アカウントを直接使わない)
  - そのユーザーでアプリケーションパスワードを発行し、`WP_APP_PASSWORD` に設定する(通常のログインパスワードは使わない)
  - REST API (`/wp-json/wp/v2/posts`) が有効であることを確認する
- 確認済みか未確認か
  - [確認済み] コードの実装・ロジックのレビュー
  - [未確認] 実際のWordPressサイトに対する試運転・本番投稿の動作確認(実サイトがまだ無いため)
